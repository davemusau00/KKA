# 26 - Knowledge, Meetings, Precedents and Collaboration

## 1. Knowledge management

The product should capture institutional memory so legal work is not trapped in individual inboxes or personal folders.

Knowledge types:
- precedent documents;
- clause library;
- internal practice notes;
- case-law research notes;
- court/registry procedure notes;
- negotiation playbooks;
- insurer/provider notes;
- checklists;
- matter closing lessons;
- training material;
- frequently used correspondence;
- policy documents.

Each knowledge item needs owner, curator, category, practice area, tags, jurisdiction/court relevance, source/citation metadata, review date, version and access policy.

## 2. Precedent lifecycle

```text
Draft precedent
 -> peer review
 -> partner/practice lead approval
 -> published
 -> used in matters with version reference
 -> periodic review
 -> superseded/retired
```

Generated matter documents should retain the source template/precedent version ID.

## 3. Legal research notes

A research note can link:
- authorities;
- issues;
- propositions;
- quotations within copyright limits;
- source URLs/citations;
- documents/PDFs;
- related matters;
- related precedent clauses;
- reviewer;
- update date.

AI-generated summaries, if introduced, must be labeled, source-linked and require human review before being promoted to firm knowledge.

## 4. Meetings

Meeting types:
- client consultation;
- matter team meeting;
- partner meeting;
- branch operations meeting;
- finance/reconciliation meeting;
- HR/performance meeting;
- vendor meeting;
- hearing preparation conference.

Meeting record:
- title/type;
- attendees;
- calendar event;
- matters/clients;
- agenda;
- documents;
- minutes;
- decisions;
- action items/tasks;
- approvals/instructions;
- confidentiality level;
- follow-up date.

## 5. Action items

Meeting action items should become normal tasks with due dates, owners, dependencies and links back to the source minute paragraph/decision.

## 6. Internal collaboration

Matter channels must support:
- threaded discussion;
- mentions;
- links to records;
- attachments that resolve to document records rather than duplicate files;
- message-to-task;
- decision markers;
- pinned items;
- unread state;
- search;
- retention controls;
- restricted matter membership.

A message attachment to a matter should reference the same logical document object where possible.

## 7. File notes

A structured file note is distinct from chat. It should support:
- note type;
- author/date;
- matter/client;
- participants;
- subject;
- rich body;
- privilege/confidentiality classification;
- attachments;
- related call/email/meeting;
- locked/final state;
- amendment addendum rather than destructive edits after finalization.

## 8. Expertise directory

Staff profiles may expose practice expertise, languages, courts frequently attended, skills, certifications, supervisor, current workload and internal knowledge authored. Sensitive HR data remains outside this directory.

## 9. Search

One search experience should discover authorized:
- matters;
- clients;
- parties;
- documents;
- emails/messages;
- file notes;
- knowledge;
- tasks;
- court events;
- financial references where permission allows.

Search results must respect access control at query time, not filter unauthorized results only after retrieval.
